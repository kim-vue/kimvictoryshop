# ZOOMCONNECT · 공통 ZOOMBAR 프로토타입

모든 LENS는 독립 신원을 가진 평면의 WORLD/COMPONENT입니다. 사용자·AI·MASTER·에이전트·코드는 같은 ZOOMBAR 구현으로 이동합니다. BOOKMARK는 목적지 책갈피이며, 실제 이동을 생략하는 권한이나 중간 세계가 아닙니다.

이 저장소는 **실제로 실행하고 시험한 첫 번째 공통 런타임**입니다. 전체 ASTRA PRO, REA 자동 제작 공장 또는 운영용 ZOOMCONNECT 완성품으로 표시하지 않습니다.

![실제 로컬 런타임 화면](docs/screenshots/desktop.png)

## 실행

Python 3.11 이상이 필요합니다. Python 표준 라이브러리만 사용하며 별도의 pip/npm 설치는 필요하지 않습니다. 실제 검증 환경은 Linux / Python 3.12입니다. Windows에서는 아직 직접 실행하지 않았습니다.

Windows에서 이 ZIP의 **내용물**을 `C:\project\AiWork\gpt\ZOOMCONNECT5`에 풀고 실행합니다. 기존 파일이 있다면 덮어쓰기 전에 보존하세요.

```powershell
Set-Location 'C:\project\AiWork\gpt\ZOOMCONNECT5'
py -3 -m unittest discover -s tests -v
py -3 -m zoomconnect demo
py -3 -m zoomconnect serve --port 8765
```

`py` 대신 `python`을 사용하는 환경에서는 명령 앞부분을 `python`으로 바꿉니다. 브라우저에서 `http://127.0.0.1:8765`를 열어 확인합니다. 종료는 `Ctrl+C`입니다.

화면은 격리된 예제 데이터만 사용하는 로컬 데모입니다. 종료하면 화면용 메모리 DB가 사라집니다. 코어의 파일 기반 SQLite 영속화는 별도 테스트에서 재시작·복원까지 검증합니다. 실제 서비스·결제·외부 프로그램을 호출하지 않습니다.

## 화면에서 확인할 것

1. **쿠팡 정산 북마크**를 선택합니다. `MASTER → DELIVERY → COUPANG`이라는 실제 경로가 생깁니다.
2. `[4500, 3800, 5200]`을 실행합니다. ZOOMCYCLE_CODE의 업무 반환값 대신 결과 HASH와 이벤트를 기록하고, 결과 조회에서 `13500`을 확인합니다.
3. 주체를 **AI**나 **코드**로 바꿉니다. 사용자와 다른 위치·이력을 유지합니다.
4. 지도에서 지금 이동 가능한 연결을 선택합니다. 먼 LENS를 누르는 것으로 이동을 우회하지 못합니다.
5. `zoom://world/MASTER/COUPANG` 같은 끊긴 URL을 시도합니다. 연결되지 않은 점프는 거부합니다.
6. ZOOM OUT으로 들어온 경로를 되짚습니다. 방향성 연결의 신규 역방향 진입과 이력 복귀는 다르게 다룹니다.

`MASTER` 화면 항목을 포함한 다섯 주체는 **동일 권한의 데모 주체**입니다. 드롭다운으로 운영 관리자 권한을 얻는 구조가 아닙니다. 실제 설정용 MASTER 자격 키는 화면에 제공하지 않습니다.

## 공통 코드

```python
bar = world.zoombar(actor_key)

# 책갈피로 목적지를 찾되 실제 연결을 따라 공통 zoom_in을 수행합니다.
bar.bookmark("쿠팡 정산")

parameter_hash = bar.put({
    "BASE_PIN": "DELIVERY",
    "COMMON_ACTION": "정산",
    "INNER_LENS": "COUPANG",
    "UNIQUE_ACTION": "일별 합계",
    "data": [4500, 3800, 5200],
})
bar.run(parameter_hash)  # 최종 공통 실행 경계. 반환값은 None.

event = next(e for e in bar.history() if e["kind"] == "CYCLE_DONE")
result = bar.read(event["body"]["result_hash"])
```

어떤 주체의 자격 키를 사용하더라도 같은 코드입니다. LENS 구현 객체를 전달하거나 `lens.other.internal` 식으로 접근하지 않습니다. 결과 HASH를 알고 있어도 현재 세계와 READ 권한이 맞지 않으면 데이터를 읽지 못합니다.

### 무엇을 공통화했나

- LENS 신원은 하나의 테이블로 관리합니다. `kind`는 표시 메타데이터이며 이동 질의의 분기 조건이 아닙니다.
- BRIDGE·LAYER도 같은 LENS 신원이며, 실제 연결은 방향성 관계로 표현합니다. 종류별 이동 클래스나 역할별 분기표는 없습니다.
- 연결 데이터는 실제 세계의 위상입니다. `종류 → 실행 코드`의 조건문을 배열로 옮긴 구조가 아닙니다.
- `zoom_in()`은 현재 위치·실제 연결·활성 상태·권한·경로 유효성을 모두 같은 질의로 검사합니다.
- 북마크의 경로 탐색 이후에도 각 이동은 `zoom_in()`을 통과합니다. URL도 동일합니다.
- 복귀는 방문 이력으로 처리합니다. 끊긴 조상 연결 또는 회수된 권한은 SAFE_RETURN으로 마지막 유효 경로까지 복귀합니다.
- 주체 자격 키와 세션을 함께 검증하고 MOVE·READ·WRITE·EXECUTE 권한을 분리합니다.
- 입력/결과 HASH는 현재 세계에 귀속됩니다. 결과는 감사 이벤트와 연결됩니다.

### 조건문에 대한 정확한 범위

`zoomconnect/core.py`에는 Python의 `if`, 삼항식, `match`, `while`과 중첩 속성 접근 `A.B.C`가 없습니다. LENS 이름·종류를 기준으로 한 분기표도 없습니다. AST 검사와 새로운 임의 종류의 LENS 이동 테스트로 이를 확인합니다.

**프로그램 전체에 판단 논리가 없다는 뜻은 아닙니다.** SQLite는 모든 LENS에 동일한 관계·권한 조건을 적용합니다. 공통 오류 처리에는 `try/except`가 있으며, 실행 모듈의 입력 안전검증과 HTTP/CLI/UI에는 일반적인 조건문이 있습니다. 이를 다른 파일로 옮겨 놓고 전체가 ‘조건문 0개’라고 주장하지 않습니다.

계산 모듈은 승인된 `total/count/average/min/max` 함수만 사용합니다. 이것은 LENS 종류별 이동 분기표가 아니라 실제 연산 구현 목록입니다. TYPE으로 기존 연산을 선택할 수 있지만, 존재하지 않는 새 알고리즘이 TYPE 선언만으로 생기지는 않습니다.

## 파일 구성

| 파일 | 책임 |
|---|---|
| `zoomconnect/core.py` | 인증, 공통 이동, 책갈피, URL, 권한, HASH, 계약 실행 진입점, 감사 |
| `zoomconnect/schema.sql` | 평면 LENS·연결·권한·방문 프레임·데이터·계약·감사 제약 |
| `zoomconnect/execution.py` | 외부 계약 검증과 승인된 순수 계산 함수 |
| `zoomconnect/demo.py` | 업무 이름과 연결을 담은 예제 데이터. 코어와 분리 |
| `zoomconnect/server.py` | loopback 전용 데모 HTTP 전달 경계 |
| `zoomconnect/web/index.html` | 실제 API를 사용하는 그래프·이동·계산 화면 |
| `tests/` | 이동·권한·동시성·복원·계산·HTTP 통합 시험 |
| `docs/VERIFICATION.md` | 실행한 검증과 확인하지 않은 범위 |

## 현재 범위와 남은 작업

이 버전은 평면의 방향성 연결 그래프를 사용합니다. 첨부된 과거 시뮬레이션의 `ANCHOR/MEMBER` 문맥별 보기, 렌즈/컬렉션 교대 경로, JSON 없는 저장 방식, 0~3차원 자료형과 모든 연산은 동등 구현하지 않았습니다. 원본 시뮬레이션 735행을 통과했다고 주장하지 않습니다.

ZOOMCYCLE은 정확히 다섯 요소로 해석합니다. 앞의 네 선택은 PARAMETER_HASH 안에 있으며 `Zoombar.run()`이 최종 ZOOMCYCLE_CODE 실행 경계입니다. 별도의 실행 LENS로 이동했다 돌아오는 `cycle_path` 모델은 아직 구현하지 않았습니다.

Builder는 명시적인 MASTER 자격 키가 필요한 **초기 설정 API**입니다. 운영 MASTER LENS, 일회용 승인·제안·롤백, 모든 설정 변경의 ZOOMBAR 경유는 다음 단계입니다. 현재 프로토타입을 운영 통제 체계로 사용하지 마세요.

성공한 이동·변경·실행의 감사 체인을 기록합니다. 거부된 명령의 영속 감사, 외부 앵커, 도메인별 CHECK 네 조건·LENSFIX·SELF_GROWTH·작업자 복구·REA 분석/자동 제작은 미구현입니다. 해시체인 일치를 이 전체 기능의 PASS로 승격하지 않습니다.

일반 API는 LENS 객체를 노출하지 않습니다. 악의적인 Python 코드가 같은 프로세스의 private 속성이나 DB 파일을 열어 읽는 것을 막는 OS 보안 격리는 제공하지 않습니다. 플러그인을 비신뢰 코드로 실행하려면 별도의 프로세스·권한 경계가 필요합니다.

북마크 탐색은 최대 깊이 64와 후보 10,000개로 제한됩니다. 제한된 로컬 예제에서 검증했으며 대규모 성능 수치는 측정하지 않았습니다. 감사 앵커는 동일 DB에 있으므로 DB 전체를 일관되게 다시 작성하는 공격을 외부에서 증명하는 기능은 없습니다.
